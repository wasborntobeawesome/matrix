# Video Studio v2 — security and correctness review

Scope: `video/studio` (server, modules, `static/`), the renderer `video/html`, `video/ai/worker.py`,
`video/templates/validate.py`, at commit `3f7b706` (v2 phase 4). Threat model: a local, single-user web app
on `127.0.0.1:8001` with no login. Attackers are (a) any website open in the same browser, (b) imported content
written by other people or AIs — template zips (which contain JavaScript), ComfyUI workflows, briefs, uploads —
and (c) other local programs. Every fix is covered by a test in `tests/` (148 fast + 2 slow) or, where noted, by
a scripted browser check on a test instance (:8014, its own data folder).

Severity: **High** = remote code / file read / takeover from a web page or an imported file; **Medium** =
exposure or denial of service that needs a mistake or a second step; **Low** = robustness, races, hygiene.

## Findings

| # | Sev | Finding | Fix | Test |
|---|---|---|---|---|
| 1 | High | **No CSRF / same-origin check.** Any website could send "simple" cross-site requests (text/plain JSON, multipart) to `127.0.0.1:8001`: create projects with any brief, import a template zip, queue renders / "Make video" / AI GPU jobs, upload music and portraits. The server parsed JSON regardless of Content-Type. | `security.Guard` (pure ASGI middleware): POST/PUT/PATCH/DELETE with an `Origin` that is not this server, `Origin: null` or `Sec-Fetch-Site: cross-site` → 403. No Origin (curl, scripts, inbox) stays allowed — the rule of Ovoz's `same_origin_only`. | `test_cross_origin_writes_refused`, `test_same_origin_and_tools_allowed` |
| 2 | High | **DNS rebinding.** No Host check: a page on `attacker.example` that re-resolves to 127.0.0.1 is *same-origin* with the studio and could read every project and call every API. | Host must be `127.0.0.1` / `localhost` / `::1` (or listed in `STUDIO_ALLOWED_HOSTS`) on every request, else 403. | `test_dns_rebinding_hosts_refused` |
| 3 | High | **Script injection via the renderer URL.** `/renderer/index.html?data=<url>` wrote `<script src=url>` for any URL, so a link to `http://127.0.0.1:8001/renderer/index.html?data=https://evil/x.js` ran a foreign script on the studio origin (full API access, passes any origin check). | `index.html` loads `data` only when it resolves to the page's own origin (and http/https/file). | slow `test_template_code_cannot_read_files_or_reach_the_network` (no request to the foreign script); browser check on :8014 |
| 4 | High | **Template code could read any local file while rendering and send it out.** render.py opened `file://…/index.html` with `--allow-file-access-from-files`, so `template.js` could `fetch('file:///C:/Users/…')` (verified: it read `C:\Windows\win.ini` and `studio/server.py`) and leak it with an image URL. `templates/validate.py` did the same. | render.py serves the page from a virtual origin (`http://render.studio.local`) through a Playwright route that only answers from the folders the render needs (renderer, fonts, the folders named by the timeline's `file://` URIs; data.js from memory); everything else is aborted; Chromium gets a dead proxy, no DNS, no WebRTC UDP, WebSockets closed, service workers blocked. No file-access flag. validate.py reuses it. Same frames and speed (26.6 s vs 26.6 s for 349 frames; PSNR old↔new within the old renderer's own run-to-run variation). | `test_mounts_map_and_resolve`; slow `test_template_code_cannot_read_files_or_reach_the_network`, `test_real_render_two_second_still` |
| 5 | High | **Imported template code ran in the editor page.** The transition picker did `import('/templates/<id>/template.js')` into the studio page itself (to animate transition tiles) as soon as a project using the template was opened — template code with the studio's origin and API. | Only built-in templates' code may run in the studio page; an imported template's transitions get a still tile. | :8014 browser check: an evil template's module ran **only** in the preview frame (`top` access → SecurityError, its POST blocked, no project created, `window.__pwned` undefined in the editor) |
| 6 | Medium | **Live preview frame was same-origin.** The preview iframe (`/renderer/index.html?embed`) had full access to the editor (`parent.document`), storage and the API, so template code in the preview could do anything the user can. | `<iframe sandbox="allow-scripts">` (opaque origin) driven by `postMessage` (`load` / `seek` / `play`); the renderer, template files and fonts are served with `Access-Control-Allow-Origin: *` so the module and fonts still load. Enabled only when `/api/health` reports `preview_sandbox` (an older server running against the new files keeps the old frame). | `test_template_files_are_sandboxed_and_cors`; :8014 probe from inside the frame: `origin: null`, `parent.document` / `localStorage` → SecurityError, API fetch blocked, Bold template + fonts render |
| 7 | Medium | **Stored XSS via template files.** Template SVGs (and any file) were served from the studio origin; opening `/templates/x/evil.svg` would run its script with full API access. | Every `/templates/…` response carries `Content-Security-Policy: sandbox`; `X-Content-Type-Options: nosniff` everywhere. | `test_template_files_are_sandboxed_and_cors` |
| 8 | Medium | **Unbounded request bodies.** JSON endpoints read the whole body (`await request.body()`); music / portrait / template / workflow uploads had no size check before Starlette spooled the whole multipart body to disk; only project uploads checked Content-Length (and not chunked bodies). | Per-route limits in the middleware, checked on Content-Length *and* while streaming (chunked): uploads 1.5 GB, music 64 MB, portraits 32 MB, templates 52 MB, workflows 16 MB, everything else 2 MB → 413. | `test_body_limits` (declared 2 GB, 3 MB JSON, 40 MB chunked) |
| 9 | Medium | **Template zip import gaps.** Zip-slip / `..` / absolute paths were already refused, but Windows device names (`CON.css`, `nul.woff2`), names Windows silently changes (trailing dot/space), case-duplicates, symlink entries, unlimited depth and a central directory with a million entries (parsed before any limit) were not; manifest strings / lists had no size limits; replace was `rmtree` + `copytree` (a failure left half a template) with no lock. | `_safe_rel` refuses all of the above; symlink and duplicate checks; entry count read from the end-of-central-directory record first; actual bytes capped while copying; manifest length / count limits (name 80, description 600, ≤ 40 options, ≤ 20 transitions, tokens ≤ 32 KB, option labels text only); atomic install (copy beside, swap, under a lock). | `test_zip_slip_and_unsafe_names_rejected` (12 cases), `test_symlink_entry_rejected`, `test_file_types_rejected`, `test_case_duplicates_and_code_in_theme`, `test_zip_bombs_and_garbage`, `test_manifest_validation` (11 cases), `test_template_import_api` |
| 10 | Medium | **ComfyUI URL and flags.** The external ComfyUI URL could be any host (the studio would send prompts / images there, poll it, and the UI links to it); `extra_args` could add `--listen 0.0.0.0`, `--enable-cors-header`, other folders. | 13 | Low | **Warm worker socket.** `worker.py` accepted the first connection to its announced localhost port; any local program (or a page racing with a no-cors POST) connecting first could drive it (`out` paths → write files anywhere). | The studio passes a random `STUDIO_WORKER_TOKEN`; the first line must be `{"op": "hello", "token": …}`, other clients are dropped and the worker keeps waiting. | 15 | Low | **Unbounded render workers.** `{"workers": 100000}` started that many Chromium pages. | API clamps to 1–16, render.py to 1–32; non-numbers → 422. | `test_render_request_clamps_workers` |
| 16 | Low | **Brief: internal / invalid keys survived normalisation.** Unknown top-level keys were copied verbatim, including `_lang` (marks a brief as already localised → text maps reached the renderer unresolved) and invalid `broll_provider` / `music` / `cover` / `presenter` that had just been rejected; scene keys `start` / `end` / `voiced` overrode timeline fields. | `_`-prefixed keys and the timeline's own scene fields are dropped; rejected fields are not re-added. | `test_internal_keys_cannot_be_injected`, `test_broll_provider_default_and_unknown` |
| 17 | Low | **Ducking look-ahead and hold were swapped** (found by the new tests): the music went down 0.30 s before a word and came back 0.15 s after it, the opposite of the documented 0.15 s / 0.30 s. | Gate window fixed; `MIX_VERSION` 4 so cached mixes are rebuilt. | `test_speech_gate_and_duck_curve`, `test_mix_loudness_peak_and_ducking` |

Also added: `X-Frame-Options: SAMEORIGIN` (clickjacking), `Referrer-Policy: same-origin`, `nosniff` on every response.

## Not fixed / not verified

- **GET requests are not origin-checked.** Other sites cannot read responses (no CORS), but a page can still
  trigger cheap GETs (e.g. a timeline preview that queues word timing on the CPU). Accepted for a local tool.
- **Template code in the live preview can still use the network** (the sandboxed frame blocks the studio, its
  storage and its API, not the internet). It only sees the open project's timeline (text and media URLs).
  Renders have no network at all.
- **No authentication.** Binding to anything other than loopback is still unsafe; the Host check refuses
  other host names unless `STUDIO_ALLOWED_HOSTS` lists them.
- **Worker handshake (#13) is not exercised by a test**: the worker imports torch and loads models; it was not
  started here (the GPU belongs to another job). It is backward compatible (no env var → old behaviour).
- ComfyUI's own server (nodes, `/view`, `/upload`) is out of scope; the studio never installs custom nodes.
- The running studio on :8001 still runs the old Python code until it is restarted; the static files and
  `render.py` on disk are already the new ones and are compatible with it (the preview keeps the unsandboxed
  frame until the server reports `preview_sandbox`).
